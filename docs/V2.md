# Hex iPhone v2: property memory and Globe

The integrated system supplies property memory over the Ask ledger, entity
georeferencing, the iOS Globe and web answer pins. Ask's optional scope/siteId fields
are aligned in Swift, JSON, Pydantic and TypeScript.

## Integrated wiring

- Migration 0040 exposes property views over `scan_entities`, `ask_runs`, captures
  and epochs. Capture membership determines the current site. Historical answers
  remain behind Ask's write authorization; the catalog entity router is mounted at
  `/api/v1/properties` for Globe and web pins.
- `/v1/ask` validates property site and optional scan membership, then binds the
  property tools to that UUID. Retrieved observations stay historical evidence,
  preserving their original scan frame. Mock and replay modes use the same memory.
- Pipeline catalog registration carries its georef/placement and verified fixed
  ARKit-pose provenance into capture metadata. Save-time georeferencing calls the
  v2 service; unknown heading or vertical datum leaves geo absent.
- Save-time dedupe holds a transaction lock per property, pages nearby observations
  through the real view, and persists a proposal under `attrs.identity`. It preserves
  each scan's evidence and treats multiple matches as review, without clustering.
- Home and Captures link to Globe. Real sources use the configured API; the fixture
  is labelled Simulated. Map pins use ARAnswer's shared card and can open the
  published scan preview when a web URL is configured.
- Web's existing `AnswerPinBridge` reads the mounted endpoint's `items`/`nextOffset`
  envelope. It pages in batches of 500, refreshes every minute/on refocus, and removes
  pins on site change/unmount. It adds no tool-rail button or gallery Cesium import.

The web client and iOS package use the same metadata envelope, separate from Ask:

```json
{
  "items": [
    {
      "id": "entity-observation-uuid",
      "siteId": "site-uuid",
      "scanId": "capture-uuid",
      "entity": "the unchanged Entity object",
      "observedAt": "2026-01-01T00:00:00Z",
      "uncertaintyM": 2.0
    }
  ],
  "nextOffset": null
}
```

An exactly full page has `nextOffset = offset + limit`; the following empty page ends
pagination. Clients deduplicate IDs and reject repeated/backwards offsets. Offset
pagination is deterministic for a fixed dataset, not a snapshot under concurrent writes;
clients refresh to reconcile it. The 100,000-observation client ceiling fails explicitly.

## Database adapter contract

Migration 0040 supplies these read views over the existing ledger, without adding a
second entities table:

```sql
-- property_entity_memory
id uuid, site_id uuid, scan_id uuid,
label text, attrs jsonb, entity jsonb,
geo geometry(PointZ,4326), uncertainty_m double precision,
observed_at timestamptz

-- property_answer_memory
id text, site_id uuid, scan_id uuid NULL,
question text, answer jsonb, observed_at timestamptz
```

`entity` is the unchanged Entity payload. `geo` is NULL when heading/vertical placement
is unresolved; otherwise its longitude/latitude match `entity.anchor.geo` (the payload
also contains ellipsoid altitude). `attrs`/`label` must match the payload. `observed_at`
is the observation time, not upload time. `uncertainty_m` is nullable, nonnegative and
comes from georeferencing provenance. The view contains current entity rows; cross-scan identity links retain each scan's
evidence. Retrieval and mock counts describe observations, rather than linked physical
objects. The ledger does not yet keep revision history for manual entity edits.

Migration 0040 adds indexes on underlying storage:
`(site_id, created_at, id)`, a GiST expression index on `geo::geography`, and GIN on
`attrs`. Keep site/capture foreign keys and provenance constraints there. Every query
binds `site_id`; radius and nearest use PostGIS geography for metres, polygon uses
`ST_Covers` (including its boundary), attributes use JSONB containment, and time ranges
are inclusive and timezone-aware. Labels are case-insensitive literal substrings,
escaping `%`, `_`, and the escape character. Nearest has a stable ID tiebreaker and
excludes unlocated rows. Polygon holes follow the existing validated Polygon schema;
this API accepts one Polygon per query, not an antimeridian-wrapping polygon.

The DB tests use the migrated tables and views, with independent properties and scans.
They exercise spatial distances, boundary inclusion, attributes, time, pagination,
historical answers and the combined fixture Ask path.

## Georeferencing and uncertainty

`tools/pipeline/placement.py` records `p_enu = scale * rotation @ p_training + translation`.
It composes both georeferencing and later recentring, so copying only `headingDeg` would
lose the capture's actual translation. `tools/pipeline/site_frame.py` and
`app.models.epoch.SiteFrame` store the fixed ENU origin. `georef.json` supplies its
`lat/lon/height`, `uncertaintyM`, `frame.headingSource` and alignment provenance. Capture
rows store method/uncertainty summaries; they do not replace the full artifact transform.

Priority is capture georef/placement, then chosen site frame, then the best positive
horizontal-accuracy fix from `location.jsonl`. Equal-accuracy ties retain the first fix.
A complete pipeline transform is accepted only with explicit confirmation that training
retained this capture's ARKit world frame and with a known heading source (`capture` or
`exif-gps`). Without placement, an explicitly non-recentred georef frame contains the
full transform. A site origin alone proves neither session translation nor heading.

ARKit is right-handed, Y up. Heading is clockwise from north of ARKit's camera-forward
axis −Z: at heading zero, `(x,y,z) → (east=x,north=−z,up=y)`. Full pipeline matrices keep
their original convention. WGS84 conversion uses the ellipsoid's ECEF coordinates and
an orthonormal local ENU basis; its inverse handles both poles and the antimeridian.

Track alignment requires an explicit Unix timestamp for AR frame zero. The bundle's
`startedAt` and CoreLocation's UTC timestamps are not silently equated with ARKit's
relative timestamp. `Bundle.swift` stamps construction time; `ARCaptureRecorder.swift`
sets frame zero when the first frame is actually recorded. Normal-tracking frames bracket each fix and interpolate camera
translation; no extrapolation or interpolation across >1-second tracking gaps occurs.
Negative/zero GPS accuracy is ignored. A weighted rigid horizontal fit keeps ARKit's
metric scale. Acceptance policy is ≥4 pairs, ≥10 m baseline, baseline ≥3× RMS GPS
accuracy, ≤25% scale disagreement, and residual ≤2× GPS accuracy. These conservative
policies are configurable code decisions, **not calibrated iPhone accuracy claims**.
Fit uncertainty is at least the GPS accuracy; angular uncertainty grows position error
with distance from the session origin. No fit means unknown heading, never zero heading.

EntitySchema requires ellipsoid altitude. Existing CoreLocation/MSL heights and
`msl-unverified` site frames cannot honestly populate that field. Horizontal GPS fits
record provenance but leave geo absent until there is a verified ellipsoid origin **and**
a vertical session tie. Raw bundle track pairing explicitly marks its vertical as
unknown. The lower-level `TrackPair`/`fit_heading` seam accepts externally verified ENU
heights. `attrs.georeference` retains origin, height datum, heading/vertical-known flags,
origin accuracy and point uncertainty. These uncertainty values are metadata, not
additional Ask fields. No geoid download or unmeasured vertical correction is attempted.

## Cross-scan identity policy

Dedupe proposes links, never deletes observations or averages anchors. Candidates must
belong to the same property and a different scan, lie within 30 days, have normalized
label similarity ≥0.85, have ≤5 m horizontal uncertainty each, and lie within
`1 m + hypot(uncertainty_new, uncertainty_old)`. Distances are ECEF chords on the WGS84
surface, appropriate for this local, at-most ~8 m candidate range; DB candidate discovery
uses PostGIS geography. Altitude is deliberately excluded from this identity heuristic.

No candidate means `new`; one means `link` to that existing identity; several mean
`review` with no chosen identity. There is no transitive clustering, so chains cannot
merge distant objects. Retain each observation's anchor, source, masks, confidence,
attributes and timestamp. Conflicting/changing attributes stay dated observations;
never overwrite older health/condition values or combine confidence as independent
measurements. Repeated GPS observations must not reduce shared positioning error.
Persist accepted links transactionally and idempotently in B's storage, with its own
concurrency/uniqueness rules. The proposal does not itself assert a physical identity,
especially for moving objects. Thresholds require field evaluation before automatic use.

## Renderer decision

Choose **MapKit 3D for the native property map**, with property polygons (including holes),
scan footprints and answer annotations. Pin taps show a small entity card; scan taps
invoke the App's exact-capture route. With `webBaseURL`, the existing published web scan
viewer opens in `SFSafariViewController`, reusing its splat rendering and API behavior.
The fallback `view.html#siteId` shows the site's published scan, not necessarily the pinned
historical capture. Exact historical scan routing belongs to the supplied App callback.

MapKit does not render 3D Tiles or splats in the map itself. A custom native renderer or
Cesium-native integration would add unverified native build/rendering dependencies on
this Linux-only branch. The chosen split delivers a native map and an existing interactive
scan-preview path without claiming native splat rendering. If inline splats on the native
globe are required, that remains a renderer decision and a separate device-validation task.
No dependency downloads, renderer bake-off or GPU run were performed.

`GlobeDataSource` and `GlobeTransport` allow offline fixtures. `FakeGlobeDataSource` and
`GlobeDebugView`/`#Preview` run independently of the App and label every fixture Simulated.
The SwiftUI/MapKit/Safari code is guarded with `canImport` and explicitly marked unverified
on Linux. The pure Swift data, decoding, routing and pagination code runs on Linux.

```bash

(cd apps/api && heavy uv run --no-sync pytest -q tests/test_georef_entities.py)

# Web pin decoding, pagination, geometry and lifecycle without a browser/GPU
heavy pnpm --filter @twin/web exec vitest run src/features/answers --maxWorkers=4
```

On a Mac, generate the existing XcodeGen project and open `GlobeDebugView`'s preview, then
exercise the real data source on an iPhone 15 Pro or newer. Verify map framing, footprint
holes, VoiceOver labels, pin/card/scan navigation, and scan rendering under iOS 26.
An on-device walk with known control points must validate heading sign, clock correlation,
height datum and uncertainty before publishing measured anchors from phone GPS.

Before the repository gate, remove `.swift-scratch` (Prettier scans generated YAML/JSON).
Run `pnpm format:check && pnpm lint && pnpm typecheck && pnpm test` with at most four
workers; run API ruff, ruff format, mypy and non-DB tests. E2E is intentionally skipped
per this task. Remove `.tmp-test` after collecting the results. No dependencies, remote
services, builds on a GPU, deployments or workflows are needed for these local checks.
