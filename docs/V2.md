# Hex iPhone v2: property memory and Globe

This branch supplies independent property-memory services, georeferencing math, the iOS
`Globe` package, and web answer pins. The Ask and Entity transport shapes are unchanged.
Server modules are not mounted in the main application yet: job B owns Ask and its tables;
the coordinator supplies the views and wires the seams below after both branches merge.

## Integration after merge

1. **B: storage adapter.** Supply the two read views below over B's entities/answers.
   Resolve `site_id` from the stored capture/epoch relationship, not a client-supplied
   property claim. `scan_id` means the capture UUID used by Ask, not the epoch UUID.
   Do not expose private workspace answers through this public catalog router; either
   exclude them in the adapter or apply B's authorization dependency before mounting.
2. **B: georeferencing.** Before persisting a validated Entity, call `align_bundle` with
   the parsed `frames.jsonl` and `location.jsonl`, the capture's existing georef/placement
   sidecars and its chosen `SiteFrame`. Call `georeference_entity(entity, alignment)`.
   This copies the entity and stores provenance under `attrs.georeference`; unresolved
   placement removes `anchor.geo`. Persist the original observation separately if B
   retains raw device evidence. Never mark an arbitrary reconstruction as ARKit's frame.
3. **B: reasoner tools.** Call `property_scope_site(validated_request)`. Absent scope or
   `scope: scan` returns `None`; retain B's scan tools. `scope: property` requires a UUID
   `siteId`; validate access/membership and bind that UUID in the tool closures. Register
   `PROPERTY_TOOLS` and the plain functions `search_property_entities` /
   `search_property_answers` with `PostgresMemory(db)`. Tool arguments cannot override
   the bound property. Serialize datetime results with FastAPI's `jsonable_encoder`.
   Earlier answers are dated evidence, not assertions about the present.
4. **B: dedupe.** Retrieve nearby observations using a radius of
   `1 + hypot(new.uncertainty_m, 5)` metres and the ±30-day window; page through all
   candidates, excluding the current scan. Convert the metadata to `Observation` and
   call `dedupe_candidates`. Unknown geo/uncertainty skips dedupe. A truncated query must
   never be treated as an exhaustive identity search. Apply the merge policy below in
   B's ingestion transaction; this branch deliberately performs no persistent writes.
5. **API router.** Include `app.api.property_memory.router` in the existing v1 router
   (which already supplies `/api/v1`). It adds `GET /properties/{site_id}/entities`,
   read-only `POST .../entities/search` and read-only `POST .../entities/dedupe`.
   Search accepts `MemoryQuery`; GET is for scalar filters and pagination, POST also
   accepts polygon/attribute objects. Dedupe accepts `{observation, candidates}` and
   returns a proposal; it does not fetch candidates or write links. After mounting,
   export OpenAPI and regenerate TS types in the coordinator's integration commit.
   The current main-app OpenAPI is unchanged because the router is unmounted.
6. **A: navigation.** Import `Globe`, supply
   `APIGlobeDataSource(baseURL: apiRootIncludingV1)` and embed `GlobeView` in the App's
   `NavigationStack`. Home can push `GlobeView(source: source)` for the property picker.
   Captures can push `GlobeView(source: source, route: GlobeRoute(siteID: siteID,
scanID: captureID))`; the selected scan's footprint is emphasized. Supply `onOpenScan`
   to open the exact capture, or `webBaseURL` to open the published site's scan preview.
   The module exposes both route and view; the App now supplies a Globe tab.
7. **Web.** `SceneBridge` mounts `AnswerPinBridge`. Once the router exists, the active
   site's located entities appear automatically. Reads page in batches of 500, refresh
   every minute and on refocus, and abort when the query is disposed. Pins are removed
   when switching sites/unmounting and hidden in As Captured mode. No tool-rail button
   is added. `view.html`, `admin.html` and `upload.html` gain no Cesium import.

The web client and iOS package use the same metadata envelope, separate from Ask:

```json
{
  "items": [
    {
      "id": "entity-observation-uuid",
      "siteId": "site-uuid",
      "scanId": "capture-uuid",
      "entity": "the unchanged Entity object",
      "observedAt": "2026-01-01T00:00:00Z",
      "uncertaintyM": 2.0
    }
  ],
  "nextOffset": null
}
```

An exactly full page has `nextOffset = offset + limit`; the following empty page ends
pagination. Clients deduplicate IDs and reject repeated/backwards offsets. Offset
pagination is deterministic for a fixed dataset, not a snapshot under concurrent writes;
clients refresh to reconcile it. The 100,000-observation client ceiling fails explicitly.

## Database adapter contract

No speculative migration or second entities table is added. B's schema is unavailable
on this branch. These are **required view column shapes**, not migrations to run verbatim:

```sql
-- property_entity_memory
id uuid, site_id uuid, scan_id uuid,
label text, attrs jsonb, entity jsonb,
geo geometry(Point,4326), uncertainty_m double precision,
observed_at timestamptz

-- property_answer_memory
id uuid, site_id uuid, scan_id uuid NULL,
question text, answer jsonb, observed_at timestamptz
```

`entity` is the unchanged Entity payload. `geo` is NULL when heading/vertical placement
is unresolved; otherwise its longitude/latitude match `entity.anchor.geo` (the payload
also contains ellipsoid altitude). `attrs`/`label` must match the payload. `observed_at`
is the observation time, not upload time. `uncertainty_m` is nullable, nonnegative and
comes from georeferencing provenance. Publish only current entity revisions in this
view, while retaining prior observations in B's history; canonical identity links must
not erase cross-scan evidence. B decides whether counts count observations or linked
physical entities; the retrieval tool currently returns observations explicitly.

Add indexes on underlying storage, after B's migration number is known:
`(site_id, observed_at, id)`, a GiST expression index on `geo::geography`, and GIN on
`attrs`. Keep site/capture foreign keys and provenance constraints there. Every query
binds `site_id`; radius and nearest use PostGIS geography for metres, polygon uses
`ST_Covers` (including its boundary), attributes use JSONB containment, and time ranges
are inclusive and timezone-aware. Labels are case-insensitive literal substrings,
escaping `%`, `_`, and the escape character. Nearest has a stable ID tiebreaker and
excludes unlocated rows. Polygon holes follow the existing validated Polygon schema;
this API accepts one Polygon per query, not an antimeridian-wrapping polygon.

The DB fixture creates transaction-local temporary adapter tables, with independent
properties and scans. It exercises spatial distances, boundary inclusion, attributes,
time, pagination and historical answers without guessing B's ORM or migration number.

## Georeferencing and uncertainty

`tools/pipeline/placement.py` records `p_enu = scale * rotation @ p_training + translation`.
It composes both georeferencing and later recentring, so copying only `headingDeg` would
lose the capture's actual translation. `tools/pipeline/site_frame.py` and
`app.models.epoch.SiteFrame` store the fixed ENU origin. `georef.json` supplies its
`lat/lon/height`, `uncertaintyM`, `frame.headingSource` and alignment provenance. Capture
rows store method/uncertainty summaries; they do not replace the full artifact transform.

Priority is capture georef/placement, then chosen site frame, then the best positive
horizontal-accuracy fix from `location.jsonl`. Equal-accuracy ties retain the first fix.
A complete pipeline transform is accepted only with explicit confirmation that training
retained this capture's ARKit world frame and with a known heading source (`capture` or
`exif-gps`). Without placement, an explicitly non-recentred georef frame contains the
full transform. A site origin alone proves neither session translation nor heading.

ARKit is right-handed, Y up. Heading is clockwise from north of ARKit's camera-forward
axis −Z: at heading zero, `(x,y,z) → (east=x,north=−z,up=y)`. Full pipeline matrices keep
their original convention. WGS84 conversion uses the ellipsoid's ECEF coordinates and
an orthonormal local ENU basis; its inverse handles both poles and the antimeridian.

Track alignment requires an explicit Unix timestamp for AR frame zero. The bundle's
`startedAt` and CoreLocation's UTC timestamps are not silently equated with ARKit's
relative timestamp. `Bundle.swift` stamps construction time; `ARCaptureRecorder.swift`
sets frame zero when the first frame is actually recorded. Normal-tracking frames bracket each fix and interpolate camera
translation; no extrapolation or interpolation across >1-second tracking gaps occurs.
Negative/zero GPS accuracy is ignored. A weighted rigid horizontal fit keeps ARKit's
metric scale. Acceptance policy is ≥4 pairs, ≥10 m baseline, baseline ≥3× RMS GPS
accuracy, ≤25% scale disagreement, and residual ≤2× GPS accuracy. These conservative
policies are configurable code decisions, **not calibrated iPhone accuracy claims**.
Fit uncertainty is at least the GPS accuracy; angular uncertainty grows position error
with distance from the session origin. No fit means unknown heading, never zero heading.

EntitySchema requires ellipsoid altitude. Existing CoreLocation/MSL heights and
`msl-unverified` site frames cannot honestly populate that field. Horizontal GPS fits
record provenance but leave geo absent until there is a verified ellipsoid origin **and**
a vertical session tie. Raw bundle track pairing explicitly marks its vertical as
unknown. The lower-level `TrackPair`/`fit_heading` seam accepts externally verified ENU
heights. `attrs.georeference` retains origin, height datum, heading/vertical-known flags,
origin accuracy and point uncertainty. These uncertainty values are metadata, not
additional Ask fields. No geoid download or unmeasured vertical correction is attempted.

## Cross-scan identity policy

Dedupe proposes links, never deletes observations or averages anchors. Candidates must
belong to the same property and a different scan, lie within 30 days, have normalized
label similarity ≥0.85, have ≤5 m horizontal uncertainty each, and lie within
`1 m + hypot(uncertainty_new, uncertainty_old)`. Distances are ECEF chords on the WGS84
surface, appropriate for this local, at-most ~8 m candidate range; DB candidate discovery
uses PostGIS geography. Altitude is deliberately excluded from this identity heuristic.

No candidate means `new`; one means `link` to that existing identity; several mean
`review` with no chosen identity. There is no transitive clustering, so chains cannot
merge distant objects. Retain each observation's anchor, source, masks, confidence,
attributes and timestamp. Conflicting/changing attributes stay dated observations;
never overwrite older health/condition values or combine confidence as independent
measurements. Repeated GPS observations must not reduce shared positioning error.
Persist accepted links transactionally and idempotently in B's storage, with its own
concurrency/uniqueness rules. The proposal does not itself assert a physical identity,
especially for moving objects. Thresholds require field evaluation before automatic use.

## Renderer decision: stage it

CesiumJS in a bundled WKWebView is now the default Globe implementation. Apple Maps 3D
remains selectable from the debug globe picker, behind the same `GlobeRenderer` snapshot
interface. The app's Globe tab and `GlobeView` preserve native entity cards and exact-capture
callbacks. A native scan selection loads its published URL asset and flies the camera.
The existing `view.html#siteId` fallback still previews the published site rather than a
historical capture; use `onOpenScan` for an exact capture route.

The small `apps/web/globe-embed.html` target shares `createGlobeWidget`, the tile provider,
and answer-pin code with the main globe. It does not fork the renderer or mount mission
UI. `SceneBridge` remains the full web application's state adapter; the embed has a typed
native adapter. View/admin/upload remain Cesium-free. The generated engine bundle is
about 11 MB and stays out of git; iOS CI and the post-clone hook build/copy it into Globe
resources. See [Globe testing](../apps/ios/Modules/Globe/TESTING.md) for commands and limits.

The existing `splat_tiles`/package stage **already writes georeferenced 3D Tiles with
KHR_gaussian_splatting and SPZ compression**, and the web globe already loads those assets.
No duplicate output step or new flag is needed. A four-gaussian simulated fixture is
produced through that existing pipeline seam; Python checks byte identity and extension
metadata, while the web and native fixture paths load the same tileset.

`Globe/Bridge/schema.json` defines the native/JS messages once. Generated TS and Swift
Codable types share JSON fixtures, with round-trip and dispatch tests in both languages.
The bridge sends snapshots, selection and flights; pin taps open the native entity card.
Unknown IDs cannot open cards from a stale property. Fixture mode needs no API.

Phone policy starts with one scan, a 64 MiB tile cache + 16 MiB overflow, screen-space
error 32, local imagery, request-render mode and a retained/preloaded web view. The warm
start goal below 0.5 s and all Apple rendering behavior need device measurement. Linux
checks validate the transport and dispatch, not WebKit/Metal. The native-globe follow-on
is scope only in [ios-native-globe.md](ios-native-globe.md); no renderer was built.

holes, VoiceOver labels, pin/card/scan navigation, and scan rendering under iOS 26.

Run `pnpm format:check && pnpm lint && pnpm typecheck && pnpm test` with at most four
workers; run API ruff, ruff format, mypy and non-DB tests. E2E is intentionally skipped
per this task. Remove `.tmp-test` after collecting the results. No dependencies, remote
