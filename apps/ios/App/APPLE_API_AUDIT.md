# App Apple API and Swift 6 review

Reviewed 2026-11-19 for the iOS 26 / Swift 6 App target. Scope is every Swift source
under `App/`, excluding `Tests/` and `Package.swift`. Repeated calls to the same
overload are consolidated below; the file index identifies all uses. Package
sources were read only to check the App's imports, visibility and isolation.

The five existing `NavigationLink` corrections in `HomeScreen.swift` are retained.
`NavigationLink(destination:label:)` with `Label(_:systemImage:)` is documented;
the previous title-plus-system-image destination initializer is not. No additional
definite compile error was found, and no additional Swift changes were made.

This is a documentation and source review, **not an iOS SDK build**. This Linux
host has Swift 6.2 but no Xcode or Apple SDK. Apple’s live documentation includes
newer SDK changes; entries marked **example** have supporting Apple examples but
could not be verified against an exact iOS 26 declaration online. These limits
are carried into the risk list instead of prompting speculative API changes.

## Validation and remaining risk

Requested command, run with Swift 6.2 and four build jobs:

```sh
. ~/hw-tools/swift/env.sh
mkdir -p .tmp-test-r4
TMPDIR="$PWD/.tmp-test-r4" swift test --package-path apps/ios/App \
  --scratch-path ./.swift-scratch-r4/App --jobs 4
```

Result: all 9 tests passed. This tests AppSupport, not the SwiftUI App target.

Risks in descending order:

1. **Medium — Apple-target compiler passes remain unexecuted here.** Only Xcode
   can settle the exact iOS 26.2 imported actor/Sendable annotations and Swift 6
   region diagnostics. Source review found no additional definite violations;
   that is not proof of an App build passing.
2. **Low — documentation declaration gaps.** Current Apple pages select
   MapContent rather than View ForEach overloads, omit the old orientation-based
   ARFrame transform declaration, add newer task parameters, and fail to expose
   some legacy initializer/overload pages. Apple examples support the unchanged
   calls, but exact historical SDK declarations were not all retrievable. The
   existing module builds are corroborating evidence only, not an App compile.
3. **Low, runtime — existing compatibility assumptions.** Main-thread delegate
   delivery and the immutable ARFrame transfer justify existing preconcurrency /
   unchecked boundaries. They require a device run for runtime validation;
   this compile-only review made no lifecycle or recording behavior changes.
